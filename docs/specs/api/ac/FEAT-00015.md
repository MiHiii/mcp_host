# FEAT-00015 — Acceptance Criteria (Web UI + Token Proxy)

> Owner: BA | Date: 2026-08-07 | Status: Draft
> Maps 1:1 to the automated/integration checks in TDD §6 (U1–U9).
> Spec: `docs/specs/api/web-ui.md` | Contract: frozen `docs/specs/api/gateway.md`

## Feature: Web chat UI with server-side token proxy

### AC-1 — Happy path: streamed answer

```gherkin
Feature: Web chat UI

  Scenario: User sends a prompt and sees the full streamed answer
    Given a gateway is running and the proxy env has GATEWAY_URL and GATEWAY_TOKEN
      And the browser opens the chat page
    When  the user submits a non-empty prompt "List files in sandbox"
    Then  the UI posts it to /api/chat with no Authorization header in the browser
      And the UI renders an event:start
      And the UI renders the tool stream events in arrival order
      And the UI renders the event:final text as the assistant answer
    And   the UI reaches a terminal state with exactly one final event
```

### AC-2 — Proxy holds the token; browser never sees it

```gherkin
Scenario: Token never reaches the browser
    Given the gateway requires Authorization: Bearer
    When  the UI sends a prompt through /api/chat
    Then  the proxy adds the Authorization header server-side
      And no client artifact (JS, source map, SSR HTML) contains the GATEWAY_TOKEN value
      And no Authorization header is sent by browser-initiated fetch
```

### AC-3 — Streamed error renders an error banner

```gherkin
Scenario: Gateway fails mid-stream
    Given a running gateway that will emit an in-stream error event
    When  the user submits a prompt and the stream emits event:error
    Then  the UI renders an ErrorBanner with the sanitized message
      And the stream terminates and the UI returns to an idle input state
    And   the token value does not appear in the error payload
```

### AC-4 — Pre-stream gateway failure is forwarded with status

```gherkin
Scenario: Gateway rejects the request before streaming
    Given a gateway that returns 401 (bad token) or 429 (over concurrency cap)
    When  the proxy calls the gateway and receives a non-200 JSON envelope
    Then  the proxy returns the same status and sanitized JSON envelope to the UI
      And the UI renders an ErrorBanner (no SSE frames shown)
```

### AC-5 — Client abort cancels upstream

```gherkin
Scenario: User navigates away or aborts mid-stream
    Given a stream in progress
    When  the user aborts (AbortController / closes the page)
    Then  the upstream gateway request is aborted via req.signal
      And no orphaned MCP child process remains on the gateway side
```

### AC-6 — Proxy is passthrough, not buffered

```gherkin
Scenario: Streaming is not delayed by the proxy
    Given a gateway that flushes events incrementally
    When  the proxy receives the upstream stream
    Then  the proxy returns the response body as a ReadableStream relay
      And the proxy never calls resp.json()/resp.text() on the stream
      And Cache-Control: no-cache and X-Accel-Buffering: no are set
```

### AC-7 — Same origin; no CORS

```gherkin
Scenario: UI and proxy are same-origin
    Given the UI is served by the same Next.js app as /api/chat
    When  the browser calls POST /api/chat
    Then  no CORS preflight is required or configured
```

### AC-8 — Input validation (boundary)

```gherkin
Scenario Outline: Prompt validation at the proxy
    Given a prompt of "<prompt>"
    When  the UI submits it to /api/chat
    Then  the result is "<result>"

    Examples:
      | prompt                        | result                          |
      | "hello"                       | proxied to the gateway (200 SSE) |
      | ""                            | proxy 400 VALIDATION_FAILED      |
      | "   " (whitespace only)       | proxy 422 INVALID_CONTENT        |
      | a 1MB prompt (oversized body) | proxy 400 / request rejected     |
```

### AC-9 — Go tree untouched

```gherkin
Scenario: Go code unchanged by the UI
    Given the web/ workspace is added
    When  CI runs the Go gates
    Then  go test ./... and go vet ./... remain green with zero Go source changes
```

### AC-10 — web/ quality gate green

```gherkin
Scenario: Frontend CI gate blocks bad builds
    Given a change to web/
    When  CI runs npm run lint && npm run typecheck && npm run test && npm run build
    Then  the gate is blocking and must be green to merge
```

## Out of Scope (MVP)

- User accounts / per-user auth on the UI (open access; token only server-side).
- Chat history persistence / multi-thread management.
- Token auto-rotation UI; rate limiting per client beyond the gateway cap.
- Any change to the frozen gateway contract `POST /v1/chat`.
