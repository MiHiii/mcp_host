# FEAT-00021 — Acceptance Criteria (Web Threads + History Cache + Token Reduction)

> Owner: BA | Date: 2026-08-07 | Status: Draft
> Maps 1:1 to the checks in TDD §6 (U1–U10).
> Spec: `docs/specs/api/web-threads.md` | ADR: `docs/adr/ADR-0010-client-thread-cache-compaction.md`

## Feature: Multi-thread chat with local history cache and input-token reduction

### AC-1 — Create / switch / archive threads; each keeps its history

```gherkin
Feature: Multi-thread chat

  Scenario: Continue a conversation as a distinct thread
    Given an active thread view with a send bar
    When  the user creates a thread, sends a prompt, then switches to another
          existing thread and back
    Then  each thread preserves its own message history
      And the active input persists per thread
```

### AC-2 — Rehydrate the last active thread on reload

```gherkin
Scenario: Reload restores the previously active thread
    Given at least one thread was created and persisted
    When  the page is reloaded
    Then  the last active thread is rehydrated with its message history
      And  its cached messages render (read-only) with the live stream area empty
```

### AC-3 — Continued-turn prompt is smaller than full history

```gherkin
Scenario: Token reduction above the compaction window
    Given a thread with more than `window` (default 6) messages
    When  the user sends another prompt
    Then  the compacted prompt size is strictly less than the full-history prompt size
      And  the last `window` messages appear verbatim
      And  the older prefix is represented by a summary placeholder
```

### AC-4 — Compaction boundary at the window

```gherkin
Scenario Outline: Compaction boundary behaviour
    Given a thread with "<count>" messages and window = 6
    When  the user continues the thread
    Then  the result is "<result>"

    Examples:
      | count | result                                                                 |
      | 6     | no compaction — all 6 messages sent verbatim                        |
      | 7     | 1 message compacted away; last 6 verbatim + summary placeholder     |
      | 3     | no compaction — all 3 sent                                         |
```

### AC-5 — Streaming appends to the thread and still renders live

```gherkin
Scenario: Streaming works per thread
    Given an active thread
    When  a prompt is sent and the gateway returns SSE
    Then  the UI renders `start → stream* → final|error` live as before
      And  the final/stream text is appended to the active thread's history cache
```

### AC-6 — Abort on switch/archive cancels the in-flight request

```gherkin
Scenario: Switching threads cleans up in-flight work
    Given  a stream in progress on thread A
    When   the user switches to thread B
    Then   the in-flight request for thread A is aborted
      And  no orphaned gateway/MCP request remains from thread A
```

### AC-7 — Go tree untouched

```gherkin
Scenario: Go code unchanged by threads
    Given  web/ gains thread + compaction logic
    When   CI runs the Go gates
    Then   go test ./... and go vet ./... remain green with zero Go source changes
```

### AC-8 — web/ quality gate green

```gherkin
Scenario: Frontend CI gate still blocks bad builds
    Given  a change to web/
    When   CI runs npm run lint && npm run typecheck && npm run test && npm run build
    Then   the gate is blocking and must be green to merge
```

### AC-9 — No gateway contract or public endpoint change

```gherkin
Scenario: Contract frozen
    Given  FEAT-00021 exposes no new endpoint
    When   the proxy and gateway receive a continued-thread prompt
    Then   POST /api/chat still accepts only {prompt}
      And  POST /v1/chat is unchanged
```

### AC-10 — No secrets/PII cached; sanitized render

```gherkin
Scenario: Thread cache is safe
    Given  threads are persisted in localStorage
    Then   no thread contains a token value or Authorization header
      And  message text is rendered as text (sanitized, no unsafe HTML)
```

## Out of Scope (MVP)

- Server-side persistence / sync / multi-device / accounts / per-user auth.
- Individual-message edit/delete (only whole-thread archive/clear).
- Cross-thread context sharing.
- `/summarize` gateway LLM compaction seam (reserved for a follow-up).
- Any change to the frozen gateway contract `POST /v1/chat` or the Go tree.
